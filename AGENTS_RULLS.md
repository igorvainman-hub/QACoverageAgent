# AGENTS.md — Правила работы 

## Контекст проекта
QA Coverage Agent — это Python-приложение, которое:

1. **Парсит документацию** — читает описание функций и сценариев из Markdown/текстовых файлов в папке `docs/`
2. **Строит матрицу трассируемости** — сопоставляет сценарии из документов с существующими тест-кейсами из `checklist.csv`
3. **Выявляет пробелы** — идентифицирует недокрытые функции и сценарии
4. **Генерирует тест-кейсы** — создаёт новые ручные тест-кейсы для выявленных пробелов
5. **Экспортирует в Xray** — добавляет кейсы в `checklist.csv` в формате, совместимом с Jira Xray Test Case Importer

**Ключевая цель:** найти пробелы в логическом тестовом покрытии функциональности проекта.

## Главное правило: ничего без подтверждения

Перед КАЖДЫМ шагом (изменение кода, новый файл, установка пакета, запуск скрипта,
рефакторинг, удаление, изменение конфигурации) обязателен цикл:

1. **План** — коротко опиши, что собираешься сделать и зачем.
2. **Стоп** — жди ответ пользователя.
3. **Действие** — выполняй только после явного "да" / "ок" / "делай".

Если пользователь отвечает "нет", "стоп", "не то" — откажись от плана и предложи
альтернативу или уточни, что не так. Не продолжай молча.

## Формат плана перед действием

Показывай план в таком виде:

```
ШАГ: <короткое название>
Что сделаю: <1-3 пункта>
Файлы: <какие затронуты>
Зачем: <в одном предложении>
```

Затем явно спроси: "Делать?" — и жди ответа.

## Что запрещено без отдельного явного разрешения

- Удалять файлы или директории
- Менять структуру данных / схему БД
- Устанавливать/обновлять зависимости
- Пушить в git или создавать коммиты
- Запускать любой скрипт, который делает сетевые запросы или тратит API-кредиты

## Гранулярность шагов

Дроби задачи на маленькие шаги. Не объединяй "написать функцию + написать тесты +
проинтегрировать" в один шаг — это три шага, три подтверждения.

Если задача большая (например, "добавь новый агент") — сначала покажи общий план
из шагов (список), дождись подтверждения плана целиком, а затем всё равно
подтверждай каждый отдельный шаг перед выполнением.

## Что можно делать без подтверждения

- Читать файлы, искать по коду, объяснять существующую логику
- Отвечать на вопросы о коде
- Предлагать варианты (без применения)

## Стиль

- Без лишних вступлений и воды.
- Код — с комментариями на английском (как в остальном проекте).
- Если не уверен в контексте (например, не понятно, какой агент имеется в виду) —
  сначала уточняющий вопрос, потом план.
